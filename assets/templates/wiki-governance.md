# MyKnowledge Wiki Governance

本文件是 MyKnowledge 的知识库治理细则。只有当任务涉及 Raw/Wiki 晋级判断、主题总览页/MOC、PARA 辅助视角、轻模板、行动项整理、健康检查或治理记录时，Agent 才读取本文件。

`system/wiki-harness.md` 仍是最高层执行规范。本文件只补充治理判断和推荐内容形式，不替代 Harness。

## Raw / Wiki 晋级判断

`/raw` 是低摩擦收集区，用来保存原始输入。以下内容默认先进入 `/raw`：

- 截图、录音转写、会议原文、聊天记录、文章全文、网页摘录。
- 只有“以后可能有用”的素材，尚未判断重要性。
- 噪音较多、上下文不完整、还不能回答明确问题的材料。
- 尚未用自己的话提炼结论、判断、口径或方法论的内容。

`/wiki` 是结构化知识层，是 Agent 查询和复用的唯一知识源。内容进入 `/wiki` 前，应至少满足以下条件：

- 已经提炼出用户自己的判断、结论、规则、方法、口径或可复用素材。
- 能回答一个明确找回问题。
- 未来会被复用在方案、汇报、问答、训练、博客或决策中。
- 能判断 `domain/scope/topic` 和 `primary_entry`。
- 可以补齐最小 metadata，或明确标为 `draft`。

中间状态允许使用 `status: draft`。`draft` 表示已进入 Wiki 整理流程，但不能直接作为最终口径。

## MOC / 主题总览页

长期主题的总览页本质上是 MOC（Map of Content，内容地图），在 MyKnowledge 中称为“检索地图”。

检索地图的目标是回答：用户或 Agent 想找这个主题下的内容时，应该从哪里进入。

检索地图不承载全部正文，不复制其他页面内容。它只负责：

- 说明这个主题是什么。
- 按找回问题组织入口。
- 列出当前重要页面。
- 标明历史、归档或已过时页面。
- 必要时补充相关对象、近期变化和边界说明。

推荐结构：

```md
# 主题名

## 这个主题是什么

## 我该从哪里找

- 找当前总体口径：[[页面]]
- 找会议记录：[[页面]]
- 找整改或风险：[[页面]]

## 当前重要页面

## 历史与归档
```

当总览页越来越像正文汇编，说明入口过多或分类过细，应合并入口，而不是继续堆内容。

## PARA 辅助视角

PARA 只作为页面性质判断视角，不替代现有 `domain/scope/topic/primary_entry/secondary_entries/status/objects` 元数据。

可选判断：

- `project`：有目标、阶段和终点的当前项目或任务。
- `area`：长期维护、没有明确终点的领域。
- `resource`：素材、方法、模板、参考资料或外部摘录。
- `archive`：历史版本、旧会议、过期计划或追溯材料。

不要为了引入 PARA 批量改造旧页面。只有在整理具体主题且确实能降低检索成本时，才可考虑逐步补充 `para_type` 等辅助字段。

## 轻模板

模板只提供推荐内容形式，不强制所有页面套用。若材料已有更自然结构，应优先尊重材料本身。


## 行动项写法

行动项使用统一写法，方便后续检索和汇总：

```md
- [ ] 负责人：事项，截止：YYYY-MM-DD
```

无明确负责人时：

```md
- [ ] 事项，截止：YYYY-MM-DD
```

已完成行动项使用 Markdown 任务完成状态：

```md
- [x] 负责人：事项，完成：YYYY-MM-DD
```

## 治理记录

治理记录写入 `/wiki/governance-log.md`。该文件只记录健康检查、结构性治理变更、发现但暂不处理的问题和后续建议，不作为规则源。

结构性变更仍按 Harness 要求写入 `wiki/log.md`。
